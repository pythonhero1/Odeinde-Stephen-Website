# Plan before implementation

For source, configuration, dependencies, CMS schema, publishing or migration work, create the plan in `plans/` using all 14 sections of `plans/README.md`. Include exact affected files, interfaces with status, quoted criteria, ordered checks, rollback, and at least three real rated objections. Use two only for a one-file change without dependency/contract changes.

Report plan path, verdict and material objections. Wait for Stephen's `APPROVE` or `APPROVE WITH CHANGES`, then record his exact words/date/scope. Do not treat interview answers or the launch target as architecture, spend or implementation approval. Planning/research, source audits and memory documentation may proceed without a code approval.

Once approved, complete its authorized steps without asking repeatedly. A material requirement/approach change requires a revised concrete plan. Paid activation and live cutover each need specific review; present cost or DNS/recovery details first. Do not loosen root rules without Stephen's approval.

Use evidence-backed status. The agent's final implementation status is `IMPLEMENTED - AWAITING STEPHEN CONFIRMATION`. Only Stephen confirms completion. Keep deviations and real verification current. Never declare tests passed without running their actual behavior or hide unfinished work as uncheckable.
