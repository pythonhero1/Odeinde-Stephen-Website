# Editor guide: intended workflow

Status: design guide to validate against the finished implementation. Replace illustrative control names with the real ones during handover; do not describe planned UI as already available.

## Pages

Open WordPress Pages and select the page. Edit named fields for the hero and sections. Reorder or add an approved section type, select real media with useful alt text, and choose related published projects/articles. Keep factual claims, pricing and testimonials consistent with their approved sources. Preview the actual frontend before publishing.

## Blog

Use Posts and the native block editor. Supply title, slug, excerpt, featured media, author/date and an appropriate category. Use the supported block set documented in the final implementation. Write useful original content answering a distinct question; avoid fake case outcomes or duplicate country pages. Preview, review Rank Math fields, then publish.

## Case studies and portfolio

Use the verified project content type. Record goals, scope, technology, Stephen's work, evidence images, actual outcomes and any limitations. Related portfolio/case study cards should use these same records so labels, images and destinations remain consistent. Do not edit loop variables in raw Divi JSON to add projects.

## SEO

Edit titles, descriptions, social image and relevant schema inputs in Rank Math. The frontend must display the values through its integration; confirm the published HTML after changes. Do not assume a plugin score proves public indexability or ranking. A slug change can require a frontend redirect and should follow the documented review process.

## Booking and contact

Change the shared booking URL once in site settings if the Cal.com event changes. Test every type of booking CTA after an edit. Enquiries should appear in the private WordPress view and notify the verified mailbox. Check both storage and inbox; report mail failures rather than repeatedly asking the visitor to resubmit.

## Publishing and recovery

Routine edits should refresh automatically. Use the verified manual refresh/retry procedure if an event fails. Never paste application passwords into browser forms or public content. Ask the maintainer before changing global URL, robots or caching settings. Keep backups and practice the recorded restore procedure before an emergency.
