# Launch checklist

Target: 24 October 2026, Africa/Lagos. Every box starts unchecked. A date or planned constant is not evidence that a criterion passed.

## Scope and content

- [ ] All eight supplied page references are implemented and reviewed.
- [ ] Every published route and in-scope destination has a documented source and correct path.
- [ ] Linked routes without dedicated exports are exported/created or changed with Stephen's approval.
- [ ] Homepage, header/footer, About destination, portfolio, insights and legal links are complete.
- [ ] No raw Divi variables, copied labels, placeholder stars, missing hero or invented testimonials/outcomes.
- [ ] Final pricing and enquiry budget currencies are approved.
- [ ] Pipe Patch Pro evidence and delivery qualifications are accurate.
- [ ] Checklist download and delivery flow genuinely work, or its reviewed content decision is recorded.

## Editing and integration

- [ ] WordPress controls page text, images, section ordering, projects, articles, global settings and SEO.
- [ ] Public CMS responses cannot expose drafts, private content, enquiry records or secret settings.
- [ ] Preview displays the latest unpublished ACF/content changes and invalid links fail safely.
- [ ] Exit preview restores normal public content and no draft response is publicly cached.
- [ ] Publish/update/unpublish/delete and slug/meta/menu changes refresh all dependent views correctly.
- [ ] WordPress API pagination includes all content and empty/error states are honest.
- [ ] Contact form validates, resists abuse, stores private records and proves real inbox delivery.
- [ ] Failed submissions, retries and email failure produce truthful behavior without lost/duplicate leads.
- [ ] Every booking CTA uses `https://cal.com/oderinde/free`; the actual event opens and is available.
- [ ] Portal and external social/review links are checked; an illustration is labeled and accessible.
- [ ] Frontend analytics/tracking works as configured and respects reviewed consent decisions.

## Rendered quality

- [ ] Production build, ESLint, TypeScript and meaningful critical tests pass.
- [ ] PHP syntax and real CMS integration checks pass.
- [ ] Complete internal link and anchor crawl passes; unknown URLs return real 404s.
- [ ] Desktop/tablet/mobile, intermediate width, keyboard, focus, zoom and reduced motion are reviewed.
- [ ] Accessible menu, FAQs, forms, errors, labels and contrast are verified in rendered context.
- [ ] Hero crop, responsive media, dimensions, image alternatives and font loading are reviewed.
- [ ] Performance measured on realistic pages; lab/field results distinguished and regressions addressed.

## SEO and production

- [ ] Old URL/SEO/redirect/media baseline captured before cutover.
- [ ] Public HTML includes real content and correct title, description, canonical, OG data and applicable schema.
- [ ] CMS origins do not leak into public canonical/schema links; no duplicate schema ownership.
- [ ] Public frontend indexable; preview/staging and CMS duplicate HTML controlled appropriately.
- [ ] Sitemap has only canonical public indexable URLs; robots and Search Console settings verified.
- [ ] Existing valuable paths, redirects and old `/wp-content/uploads/` image URLs continue to resolve.
- [ ] CMS origin and media reachable from the deployed frontend; no `.local` origin in remote settings.
- [ ] Complete locally tested release is pushed to GitHub; remote commit/tag verified before migration.
- [ ] Protected remote preview uses the intended release and real remote CMS, with all critical checks passing.
- [ ] Frontend hosting budget/spend settings approved; CMS space/limits/SSL verified.
- [ ] Backup restore tested; untouched original installation and recorded DNS rollback targets retained.
- [ ] Cloudflare DNS snapshot recorded; mail and portal records preserved.
- [ ] Stephen approves the exact release, content freeze, changed DNS records and rollback.
- [ ] Public domain, SSL, canonical host, cache, forms, booking, media and admin checked after change.
- [ ] Handover/owner access and editing/deployment/restore instructions verified.
- [ ] Stephen's completion confirmation recorded with date and any accepted limitations.

Attach evidence to the relevant plan or readiness report for each criterion. An unchecked mandatory item blocks launch until resolved or its scope is explicitly changed by Stephen. Do not automatically tick boxes after a script merely exits zero.
