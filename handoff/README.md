# Handoff documents

Use a matching file name for each plan that depends on an external integration or leaves an unresolved contract. Write for someone who can act without seeing the agent conversation.

Include the purpose, exact interface, confirmed schema and examples redacted of private data, authentication method without secrets, error behavior, outstanding decisions, verification evidence and a clear next action. Label each interface VERIFIED, PROPOSED or OPEN. Identify mocks explicitly; do not present their shape as a verified provider API.

For production handover also include account ownership, CMS editing instructions, environment variable names, deployment procedure, backups/restore evidence, DNS changes and rollback. Never include passwords, tokens, production leads, or private client files.
